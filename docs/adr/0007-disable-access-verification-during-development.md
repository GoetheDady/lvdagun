# 开发阶段不实施访问验证

当前开发阶段从本地服务与客户端中彻底删除 token 认证,任何实际可达的客户端都可以调用全部 API 与 Agent 能力。这样可以消除 URL token、浏览器持久化与双模式认证分支带来的使用和维护成本;何时重新设计访问验证,只由后续明确的产品决策决定,当前不预设触发条件或实现挂钩。

**Status**: accepted

**Considered Options**:

- 保留 URL token:能降低 localhost CSRF 风险,但跨浏览器使用不便,且 token 会进入 URL 和浏览器存储。
- 仅开发模式绕过认证:保留一条开发期间不被实际使用、容易失效的认证路径。
- 完全删除访问验证(选中):当前代码只承载正在使用的开发形态,未来按当时的访问边界重新设计。

**Consequences**:

- 本次不修改监听配置,本地服务继续使用现有监听地址。
- 明确接受可达客户端读取模型 API Key、消息历史,以及通过 Agent 调用 `read`、`bash`、`edit`、`write` 等能力。
- 明确接受开发阶段的 CSRF、DNS rebinding 与本机其他进程直接访问风险。
- 不保留认证开关、空中间件、Adapter、TODO 或迁移逻辑;已有浏览器中的 token 值不再读取。
