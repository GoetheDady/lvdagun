# 由内置 Extension 管理待处理消息

待处理消息属于驴打滚的产品状态,不以 Pi 原生 steering 和 follow-up 队列作为权威来源。Agent Hub 显式加载一个驴打滚内置 Extension,由它持有带稳定身份的待处理消息并提供逐条调整方向、删除和整队取回能力;当前处理路径结束时,Extension 再通过 Pi `followUp` 逐条移交排队消息,调整方向时则通过 Pi `steer` 移交。这样既能实现逐条交互和多客户端一致状态,又能复用 Pi 的 Agent 生命周期、自动重试与上下文压缩语义,无需修改 Pi SDK 或按文本重排其内部队列。

磁盘资源目录中的外部 Extensions 继续保持关闭;显式加载内置 Extension 不表示开放 Extension 发现或预先建设外部扩展基础设施。待处理消息一旦移交给 Pi,即视为已经开始处理,不再允许取回或删除。

**Considered Options**:

- 直接使用 Pi 原生队列:能够排队和整队清空,但消息没有稳定身份,无法可靠支持逐条调整方向和删除。
- 给 Pi SDK 打补丁:可以补齐原子队列操作,但待处理消息是驴打滚的产品能力,不应把产品状态所有权下推到依赖包。
- 在 Agent 完全稳定后由 Agent Hub 启动新提示:实现独立于 Extension,但会割裂 Pi 的重试、上下文压缩和队列续跑生命周期。
- 使用内置 Extension(选中):在 Pi 生命周期内移交消息,同时由驴打滚保留队列所有权。

**Consequences**:

- 首版待处理消息仅随当前 Runtime 存在,本地服务退出或崩溃后不恢复;跨进程持久化及严格的不重复、不丢失保证另行设计。
- 每条待处理消息具有稳定身份,首版支持逐条调整方向和删除,以及整队取回和丢弃;不提供编辑、排序或更多菜单。
- 排队消息按先进先出顺序逐条移交。只有当前处理成功自然结束时才自动移交下一条;当前运行最终失败时保留尚未移交的消息并暂停自动出队。
- 用户停止 Agent 运行时先禁止自动移交,再取回全部待处理消息并停止 Pi,避免停止后继续运行。
