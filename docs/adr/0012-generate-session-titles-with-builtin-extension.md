# 由内置 Extension 生成会话标题

自动标题是首轮 Agent 运行完全结算后触发的确定性产品能力,由 Agent Hub 显式加载的内置 Extension 完整负责触发判断、一次性尝试标记、模型调用、结果校验和标题写入。Extension 在 `agent_end` 记录最终稳定前的运行是否成功,等待待处理消息、自动重试和上下文压缩全部结束并收到 `agent_settled` 后,才根据首条用户消息和首条成功回答启动生成。

标题生成继续使用当前会话模型,Extension factory 接收 Agent Hub 已创建的 Pi `ModelRuntime`,不增加标题专用模型或配置。模型调用在后台非阻塞执行;失败不重试,写入前后都检查手动标题,会话关闭时中止未完成任务,避免重复计费、覆盖用户操作、产生关闭后的迟到写入或延迟 Pi 的结算线路。一次尝试标记先于模型调用持久化,即使任务被中止也不在会话重新打开后重试。

当前处于开发阶段,尝试标记直接采用 Extension 自己的新命名;旧会话数据清空,不读取旧标记,也不增加迁移或兼容线路。

选择内置 Extension 是为了让依赖 Pi 生命周期和会话持久化的标题行为集中在 Pi 原生 seam,而不是混入负责事件与状态投影的会话适配器。磁盘资源目录中的外部 Extensions 继续保持关闭,自动标题 Extension 也不构成开放外部扩展基础设施。

**Considered Options**:

- 由会话适配器监听 Pi 事件并生成标题:实现直接,但把独立产品功能与 Pi 事件投影混在同一 module。
- Extension 只监听事件并回调外部标题模块:减少适配器代码,但标题规则和生命周期所有权仍跨越两个 module。
- 由内置 Extension 完整管理(选中):复用 Pi 原生生命周期、持久化条目和会话标题能力,并把自动标题知识集中在一个 module。
