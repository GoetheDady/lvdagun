# 使用上游 Todo Extension 管理会话执行计划

驴打滚使用 [`@juicesharp/rpiv-todo`](https://github.com/juicesharp/rpiv-mono/tree/main/packages/rpiv-todo) 作为会话执行计划的状态与生命周期实现,由 Agent Hub 将它作为内置 Extension 显式加载;磁盘目录中的外部 Extension 发现继续关闭。这样可以复用成熟的计划依赖、回放、清理、提醒和批量操作语义,而不在产品代码中维护第二套 Todo 状态机。

**Status**: accepted

Extension 完整拥有会话执行计划的行为规则。驴打滚只在 `apps/backend/src/extensions/todo/` 放置产品适配器和 `UPSTREAM.md`,负责装配上游 Extension、校验并投影产品所需状态、记录上游来源和更新方法;Agent Hub、产品历史和 Web 都不得重复解释 Todo 动作或状态转换。首版依赖精确锁定 `@juicesharp/rpiv-todo@2.6.4`,通过 Bun 手动升级并验证,不使用 git submodule,也不复制或本地修改上游源码。需要调整上游行为时优先向上游贡献,再通过版本升级消费。

Pi 执行历史中的 `toolResult.details` 保存 Extension 的完整快照,Extension 从当前 Pi 分支最后一个有效 Todo 结果恢复状态。产品历史只持久化经过校验的展示投影,用于进程重启恢复、断线快照和多客户端同步;收到非法快照时保留上一份合法投影。分叉会话和编辑重发继承所选历史点所在分支的计划快照,不从源会话当前叶节点复制状态。

会话执行计划跨 Agent 运行、停止、页面刷新、上下文压缩和服务重启持续存在,直到 Agent 为新的复杂目标清空或替换。Agent 自主为复杂工作创建并更新计划,简单工作和普通对话不使用;用户只读查看,通过发送消息改变目标。计划内容使用中文 `subject`、`activeForm` 和说明,持久化的 action 与 status 值保留上游英文值。

Todo 是会话执行计划的内部机制。Web 不在当前或既有产品会话历史中渲染 Todo 工具运行卡片,无论调用正在执行、已完成还是失败;底层执行历史和产品数据仍保留对应事实。单次 Todo 失败不单独向用户告警,只有它最终导致 Agent 运行失败时,才由已有运行级错误反馈承接。

产品投影显示为输入框上方居中的紧凑胶囊:默认显示“第 X / Y 步”和当前进行中步骤,优先使用 `activeForm`,否则使用 `subject`。Todo 更新期间继续显示上一份合法投影,直到新投影一次性替换。只有鼠标悬停约 100ms 后展开详情,鼠标离开胶囊和面板约 150ms 后关闭;不提供点击、键盘或移动端展开。详情按创建顺序显示未删除步骤,最多约八行后内部滚动,不展示依赖关系。全部步骤完成后保留 `Y / Y` 到下一次 Pi `turn_start`,随后隐藏。

Web 在当前助手回复末尾使用 shadcn/ui 默认 `Marker` 持续显示运行标记。标记在提示开始处理时立即出现,不可交互,与思考块和普通工具卡片并存,并在 Agent 运行结算后直接消失。它使用旋转图标和静态文字,不使用 shimmer;单一 `role="status"` 区域只在阶段文字变化时更新。

运行标记使用产品语言表达客户端当前可判断的阶段:`正在准备回复`、`正在思考`、`正在更新执行计划`、`正在使用工具`、`正在生成回复`、`正在重试`和`正在压缩上下文`;无法可靠细分时显示`正在处理`。阶段优先级为重试或压缩、Todo 更新、普通工具、思考、生成回复、准备回复。发起停止的客户端以最高优先级显示`正在停止`,其他客户端无需同步该瞬时状态。阶段由客户端基于既有产品状态做最佳判断,不为毫秒级切换精度或多客户端停止状态扩充协议。

上游 Extension 加载失败时,当前会话静默降级为不使用会话执行计划,不向用户显示提示,只记录内部诊断;恢复后从当前 Pi 分支回放。内置集成不得创建上游默认的 `~/.config/rpiv-todo` 配置目录,首版使用固定默认值;若未来确有可配置需求,先推动上游提供可注入配置,再升级依赖使用。

**Considered Options**:

- 在驴打滚中重写 Todo:可以完全控制协议和界面,但会重复维护已有的状态机、回放与生命周期规则。
- 使用 git submodule 或复制上游源码:便于直接修改,但升级、来源追踪和本地补丁长期容易分叉。
- 直接加载上游包,不设置适配边界:代码最少,但会让上游数据结构渗入产品协议和 Web,增加升级成本。
- 使用精确版本的上游包和薄适配器(选中):保留清晰所有权和可验证更新路径,同时让产品只依赖稳定投影。

**Consequences**:

- 首次实现前必须验证上游包与当前 Pi 版本的兼容性;升级上游包时需重新验证回放、分支继承、生命周期和投影协议。
- 产品历史不是 Todo 行为的权威来源,不能从展示投影反向驱动 Extension 状态。
- 上游暂不支持或存在缺陷的行为不在本地打补丁;必要时保持相应能力关闭,等待上游修复版本。
