# 用内置 Extension 与内嵌子会话实现子 Agent 委派

驴打滚通过一个内置 Extension 提供"委派"工具:主 Agent 可以把任务委派给内置子 Agent(scout、planner、reviewer、worker)。每个子 Agent 在 Agent Hub 进程内以独立的内嵌 Pi 会话运行,子会话按父子会话 ID 关联并完整持久化;Web 在消息流中以子 Agent 卡片内联展示运行进展与最终结果。

**Status**: accepted

## 决策

### 执行形态:Hub 内嵌会话,不用子进程

官方 Pi 扩展示例(`examples/extensions/subagent/`)通过 `exec` 为每个子 agent 起独立 `pi` CLI 子进程。驴打滚不采用子进程方案,而是在 Agent Hub 进程内用 SDK 为每次委派创建独立的内嵌 Pi 会话:

- 上下文隔离目标由"每个子 Agent 一个独立会话"达成,不依赖进程边界;
- 直接复用驴打滚已配置的 Provider 凭据与会话模型,无需向子进程传递配置或管理临时目录;
- 子会话天然复用 Pi 的会话持久化,产品侧只维护父子会话 ID 关联;
- 无子进程生命周期问题(崩溃、僵尸进程、信号传播),停止操作直接取消内嵌运行。

驴打滚与终端上安装的 pi 完全独立:不读取 `.pi/`、全局 agent 目录或任何终端 pi 配置。

### Agent 定义:内置固定,不做文件发现

子 Agent 角色内置在驴打滚代码中,职责与 prompt 以官方示例验证过的定义为蓝本,不提供 `.pi/agents/*.md` 之类的文件发现、用户自定义或 Web 管理 UI。这符合"按需扩展"与"最简实现"原则;文件发现涉及信任模型与配置管理,当前没有需求。

内置四个角色,工具范围按角色定死:scout(快速侦察,压缩上下文返回)与 reviewer(代码审查)为只读;planner(实施规划)与 worker(通用执行)开放全部工具。子 Agent 继承发起会话的会话模型与思考等级;子 Agent 的可用工具中不含委派工具,即不允许递归委派。

### 委派模式:单一 + 并行,不做链式

委派工具支持两种模式:单一(一次一个子 Agent)与并行(一次派发多个子 Agent,同一会话上限 4 个,超限直接报错)。链式(`chain`,前一结果作为后一输入)与工作流 prompt 模板推迟到有真实需求再评估。

### 持久化:真实子会话 + 父子 ID 关联

每次委派产生一个真实子会话,完整保存执行内容;产品数据中记录父子会话 ID 关联,子会话内容可随时按 ID 查询。产品会话历史保存经过校验的委派投影(委派参数、状态、最终结果、用量),作为子 Agent 卡片的恢复来源。分叉与编辑重发按普通工具结果对待:已完成(含失败/中断)的委派卡片跟随所选历史点;运行中的委派不随分叉继承。子会话不出现在会话列表;永久删除父会话级联删除全部子会话,归档父会话一并隐藏子会话。

服务重启或 Hub 崩溃时,运行中的子 Agent 标记为"已中断",不恢复续跑;子 Agent 是短生命周期任务,续跑复杂度不值得。

### Web 投影:消息流内联卡片,无标签栏

流式输出期间收到子 Agent 事件时,直接在消息流中渲染子 Agent 卡片,一个子 Agent 一张卡片;运行中默认展开实时展示进展,结束后收起为摘要态(委派参数、结果、用量),保留在产品会话历史中。首版不提供点击展开完整结果与对话窗口;查看子会话完整内容的交互列入后续版本。停止主 Agent 运行级联停止该会话全部子 Agent,不提供单独停止某个子 Agent 的操作。

子 Agent 运行计入现有"正在使用工具"运行标记,不新增运行阶段;子 Agent 运行期间用户发消息仍走待处理消息排队;上下文压缩只作用于父会话。

## Considered Options

- 子进程隔离(官方示例方案):进程级隔离最彻底,但需要管理子进程生命周期、配置传递与临时文件,对单用户本地产品没有实质收益。
- 只存委派摘要,不保存子会话(曾倾向的简化):存储最省,但丢失完整可追溯性,且仍需自建一套中间流存储,不如直接复用 Pi 会话持久化。
- 链式委派与并行:并行保留(用户明确需要),链式推迟——它会让停止语义、投影协议和历史继承复杂度翻倍。
- 内嵌子会话 + 内置角色 + 单一/并行委派(选中):复用已有 Provider 配置、会话持久化与事件通道,改动集中在 Extension 装配与 Web 卡片投影。

## Consequences

- Agent Hub 需要为子会话维护独立的运行时与事件通道,并保证级联停止、并行上限和父子 ID 关联的一致性。
- 产品历史协议新增子 Agent 委派投影;子 Agent 中间流事件只在运行期间广播,不进入产品会话历史。
- 并行子 Agent 共享本机环境,工具副作用不相互隔离,与既有"并行 Agent 运行"的边界一致。
- 未来加入"点击卡片查看子会话完整内容"时,数据已经具备(子会话全量持久化),只需新增客户端交互与查询接口。
