# Domain Docs

工程类技能探索代码库时,如何消费本仓的领域文档。

## 探索前先读

- **根目录 `CONTEXT.md`**,或
- 根目录 **`CONTEXT-MAP.md`**(若存在)——它指向每个上下文的 `CONTEXT.md`,读与主题相关的每一个
- **`docs/adr/`** — 读即将动手区域的 ADR

以上文件不存在时**静默跳过**:不提示缺失,也不主动建议创建。`/domain-modeling` 技能(经 `/grill-with-docs`、`/improve-codebase-architecture` 触达)在术语或决策真正落定时才按需创建。

## 文件结构

单上下文仓库(绝大多数仓库):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用术语表词汇

输出中出现领域概念时(issue 标题、重构提案、假设、测试名),使用 `CONTEXT.md` 中定义的术语,不漂移到术语表明确回避的同义词。

所需概念不在术语表中,是个信号:要么你在发明项目不用的语言(重新考虑),要么确有缺口(记下来交给 `/domain-modeling`)。

## 标注 ADR 冲突

输出与既有 ADR 矛盾时,显式指出而非默默覆盖:

> _与 ADR-0007 矛盾——但值得重开,因为……_
