驴打滚架构理解

中心辐射式:Agent Hub(内核)+ 多端客户端。对 PRD 第 3 节的理解,非官方设计文档。

1. 一句话

一个常驻本机的 Agent 内核负责"思考"(模型对话、工具、上下文),多个无状态客户端负责"展示"。客户端随时可关、可重开、可增加;内核一直在,谁来了都给同一份上下文。

🖥 桌面壳
V0 客户端 · Electron
⇄
🧠 Agent Hub
模型对话 · 工具执行
上下文 · 会话状态
⇄
📱 手机 PWA
V2 客户端 · 局域网

2. V0 的物理形态:内核寄居在 Electron 主进程

单一安装包 · 单一进程树
渲染进程 = 客户端(无状态)
  • 对话界面:消息流、输入框、流式渲染
  • 配置向导 / 设置页
  • 不持有 Agent 状态,只有"当前显示的消息"
▲ IPC(事件流:文本增量 / turn 结束 / 错误)▼
主进程 = Agent Hub(V0 载体)
  • createAgentSession:模型对话、流式事件源
  • 会话历史 / 配置 / API Key(本机存储)
  • 窗口管理 + 托盘常驻

窗口关闭 ≠ 进程退出:Hub 随主进程常驻,窗口只是 Hub 的一个可重建的"视图"。

3. 四个关键含义

  1. 生命周期解耦 — 关窗只销毁视图,Hub 常驻;托盘"退出"才真正结束进程。会话保持(F3)靠的不是"保存窗口",而是 Hub 一直活着。
  2. 状态归属 — 上下文、会话历史、模型配置全部在 Hub 侧;渲染进程是无状态客户端,重开窗口 = 从 Hub 拉回历史继续聊。
  3. 接口即未来协议 — V0 里客户端 ↔ Hub 走 IPC,但 IPC 通道的语义按"通信协议"设计(消息增量、turn 生命周期、错误事件),而不是按"内部函数调用"设计。今天的事件流就是 V2 网络协议的设计稿。
  4. 演进靠接口稳定,不靠重写 — V1 把 Hub 抽成独立进程、V2 加网络监听,替换的只是传输层(IPC → 网络),客户端代码与 Hub 内部不用推倒重来。

4. 演进路径

V0
  • Hub 承载于 Electron 主进程
  • 单一桌面客户端
  • 本机对话 + 托盘常驻 + 首次向导
V1
  • Hub 抽成独立进程(接口不变)
  • 设备感知 + 长期记忆 + 自定义工具
V2
  • Hub 开放局域网/公网端口
  • 手机 PWA 接入同一内核

每一步都是"换个传输层/加点能力",架构骨架(内核—客户端分离)从 V0 起就不变。
