# Pi SDK 会话能力对接现状

> 更新日期：2026-08-21
>
> 对照版本：`@earendil-works/pi-coding-agent@0.84.1`

## 结论

当前已经完成 V0 所需的核心对话闭环：用户可以创建、恢复和切换持久会话，发送文本消息，在 Agent 运行期间继续排队或调整方向，查看流式回复、思考过程与工具运行，并控制会话模型、思考等级和 Agent 停止。不同会话可以同时运行。

日常使用所需的两项会话树动作也已接入：从任意已完成助手回复“分叉为新会话”，以及对当前分支最后一条用户消息“编辑并重发”。完整树浏览、已有分支切换和任意节点回退不在当前范围。图片输入等待统一附件能力再评估；导入导出、归档恢复、手动上下文压缩及会话运行设置不进入当前产品规划。会话执行计划已作为内置 Extension 接入。外部 Extensions、Skills 等资源发现能力仍是主动关闭，并非实现遗漏。

### 运行中消息与待处理消息

Pi 支持的两种运行中消息已经接入：

- `steer`：当前助手轮次完成工具调用后，优先插入新指令。
- `followUp`：等待当前 Agent 运行自然结束后，再执行后续消息。

用户在当前会话运行期间发送消息时，默认进入驴打滚的“待处理消息”区，而不是立即写入 Pi 队列。每条消息由当前 Runtime 分配稳定 ID，服务端通过 `pending_messages_changed` 广播完整权威快照，多个客户端据此展示相同的 FIFO 列表。

客户端没有直接把 Pi `queue_update` 事件投影成待处理消息列表。Pi 事件只提供 steering 和 follow-up 文本数组，没有可供逐条操作的稳定消息 ID；若以文本作为身份，重复文本、逐条删除和并发更新都会产生歧义。因此，待处理消息在移交前由驴打滚内置 Extension 管理，移交后才进入 Pi 原生队列：

- 默认排队：一次成功的 `agent_end` 只取 FIFO 首条，通过 `followUp()` 移交；最终失败时不移交，消息仍留在待处理区。
- 调整方向：用户点击指定消息的“调整方向”后，按稳定 ID 取出该条消息并通过 `steer()` 移交；Pi 拒绝时恢复到原位置。
- 逐条删除：只删除尚未移交的指定消息。
- 全部取回：从待处理区移除全部消息，并按原顺序放回当前客户端草稿。
- 清空：确认后丢弃全部尚未移交的消息，不影响已经进入 Pi 队列的消息。
- 停止：清空 Pi steering、follow-up 队列和驴打滚待处理区，中止当前运行，再把所有未处理文本按顺序恢复到发起停止操作的客户端草稿。

当前限制：

- 不支持待处理消息跨服务重启持久化；
- 编辑或重新排序待处理消息；
- 设置 `all` 或 `one-at-a-time` 投递模式；
- 带图片的排队或调整方向消息。

### 会话执行计划

复杂工作由 Agent 创建并持续维护会话执行计划，用户通过输入框上方的紧凑状态查看当前进度和计划步骤。实现按 [ADR-0015](./adr/0015-manage-session-execution-plans-with-upstream-todo-extension.md) 使用上游 `@juicesharp/rpiv-todo@2.6.4` 作为显式加载的内置 Extension，由产品历史保存经校验的 Web 展示投影。

当前能力包括：

- 在复杂目标中自动创建和更新计划,简单工作与普通对话不启用;
- 跨 Agent 运行、停止、刷新、上下文压缩和服务重启恢复;
- 分叉会话与编辑重发继承所选历史点的计划状态;
- 多客户端同步只读进度,用户通过新消息调整目标;
- Web 隐藏 Todo 工具运行卡片,以瞬时运行标记反馈当前阶段,并使用仅支持鼠标悬停展开的紧凑计划界面;
- Extension 加载失败时静默降级,不阻断会话执行。

实现没有开放磁盘 Extension 发现，不创建第二个配置目录，也不在 Agent Hub 或 Web 中复制 Todo 状态机。

## 尚未对接能力

### 1. 图片与多模态输入

Pi 的 `prompt()`、`steer()` 和 `followUp()` 均支持图片附件。客户端已经能够渲染历史消息中的图片，但发送接口当前只接受 `{ text }`。

图片输入不作为独立优先项；等产品设计统一的文件附件能力时，再一并确定选择、预览、校验、传输和排队语义。

尚未实现：

- 文件选择；
- 拖放或粘贴图片；
- 图片预览与移除；
- 图片编码、大小和 MIME 类型校验；
- JSON-RPC 协议中的附件内容；
- 携带图片发送、steer 或 follow-up。

### 2. 手动上下文压缩

自动上下文压缩已经生效并可展示，但用户不能主动调用 Pi `compact()`。

尚未实现：

- 手动开始压缩；
- 提供自定义摘要指令；
- 开启或关闭自动压缩；
- 查看当前上下文占用和压缩阈值。

停止正在进行的压缩已经由通用停止操作覆盖。

### 3. 会话树与剩余分支操作

Pi 会话内部是由 `id` 和 `parentId` 组成的树，支持在同一文件内回退，也支持从历史节点创建新会话。

已经对接：

- 客户端只使用稳定的产品 `runId` 和 `itemId`；Pi `entryId` 保存在后端来源引用中；
- 每条已完成且持久化的助手回复都可“分叉为新会话”；派生会话保留到所选回复的路径，源会话不变；
- 派生会话使用独立 JSONL 和独立 Runtime，标题为源标题加“（分叉）”，并恢复所选历史点的模型和思考等级；
- 仅当前分支最后一条用户消息可“编辑并重发”；客户端提交产品 `itemId`，后端解析对应 Pi entry 后通过 `navigateTree()` 建立新分支；
- 编辑重发前置校验失败时恢复原叶节点，旧消息和原位草稿继续显示；成功后同一会话的其他客户端通过历史变化事件切换到新当前分支。

尚未对接，也不属于本批范围：

- 通过 `getTree()` 展示会话树、当前分支和分叉位置；
- 通过 `navigateTree()` 回退到历史节点继续，并切换到已有分支；
- 编辑任意历史用户消息；
- 浏览或恢复编辑重发留下的旧分支。

“新建会话”“切换会话”和“分叉为新会话”都操作独立会话；“编辑并重发”才在原会话文件中产生新分支。

Pi 还支持为离开的路径生成分支摘要，以及为节点或摘要添加标签；这两项不是完成分支、回退和派生主流程的必要条件，暂不纳入下一步。

### 4. 导入与导出

导入导出不进入当前产品规划。

尚未对接：

- 从 JSONL 文件导入 Pi 会话；
- 将当前分支导出为 JSONL；
- 将会话导出为 HTML；
- 从客户端选择导入来源或导出位置。

此外，驴打滚当前只支持归档，没有归档列表和恢复归档会话的入口。当前不计划补充这两个入口；这属于产品会话生命周期选择，不是 Pi `AgentSession` 的直接能力。

### 5. 会话统计与上下文状态

客户端目前能查看单条助手消息的模型、Token 和费用，但没有接入 Pi 的会话级统计。

尚未展示：

- 用户消息、助手消息、工具调用和工具结果数量；
- 会话累计输入、输出、缓存 Token；
- 会话累计费用；
- 当前上下文占用；
- 历次压缩前后的统计。

### 6. 会话运行设置

Pi 提供的以下设置尚未暴露：

- 自动重试开关；
- 自动上下文压缩开关；
- steering 和 follow-up 队列模式；
- 当前活跃工具列表；
- 动态启用或停用工具；
- Runtime 资源重新加载。

Pi 的模型循环和思考等级循环也未直接接入，但当前客户端已经提供模型选择器和思考等级滑块，因此没有必要重复实现循环操作。

### 7. 直接 Bash 与自定义消息

Agent 可以通过已启用的 `bash` 工具执行命令，但用户不能像 Pi 交互模式一样直接执行 Bash，也没有对接：

- `executeBash()` 直接命令；
- Bash 输出流和单独停止；
- 排除命令结果进入模型上下文；
- `sendCustomMessage()`；
- `sendUserMessage()` 的结构化内容入口。

这类能力不是 V0 对话闭环所必需。

## 当前主动关闭的 Pi 能力

创建 Pi 会话服务时，以下外部资源发现能力被显式关闭：

- 外部 Extensions；
- Skills；
- Prompt Templates 和斜杠命令；
- Context Files，包括自动发现 `AGENTS.md`；
- Themes。

系统提示词目前使用驴打滚内置的固定提示词。工具包括 Pi 默认的四个工具和 Todo Extension 注册的 `todo`。待处理消息与会话执行计划都使用 `resourceLoaderOptions.extensionFactories` 显式加载命名内联 Extension；`noExtensions: true` 继续阻止磁盘目录发现外部 Extension。

这符合当前架构约束：Extension 只在出现已确认的具体功能需求时开发，当前阶段不预先搭建扩展基础设施。PRD 也将自定义工具和技能管理放在后续版本。

## 会话基础设施限制

### 并行 Agent 运行

不同会话拥有独立 Runtime，可以同时进行 Agent 运行。提示的异步前置校验按会话串行：同一会话中的后续提示会在前一条通过前置校验后再决定进入待处理区，不会误启动第二次运行；不同会话互不等待。

各会话的待处理消息、停止操作、状态和事件订阅均按会话隔离，但工具仍共享同一本机环境。两个并行 Agent 同时修改相同文件时可能互相覆盖，当前不提供 worktree 或路径锁。全局模型配置只能在所有会话空闲时修改；CLI 退出会停止并释放全部已加载 Runtime。

### JSON-RPC 断线恢复

客户端重新建立 WebSocket、完成 `initialize` 并恢复会话订阅。每次订阅时，服务端先订阅并暂存新事件，再用 `session/subscribe` 响应返回包含产品完整历史、活动草稿和运行状态的 `session_snapshot`，最后顺序发送暂存事件并继续实时流。客户端用快照原位替换服务端状态，已有内容立即渲染，快照后的新内容继续流式追加。

当前不提供事件 ID、事件日志或断线期间瞬时工具进度与重试倒计时的重放；连接存活使用 WebSocket ping/pong。服务进程仍在时可以恢复活动草稿；服务进程重启后恢复 SQLite 已提交内容，并把未结算运行标记为中断。Pi JSONL 丢失时产品历史仍可只读查看，但不能继续、编辑或分叉。

## 后续取舍

完整会话树浏览、任意节点回退和已有分支切换只有在用户确实需要找回旧分支时再评估；当前通过“分叉为新会话”和“编辑并重发”覆盖明确的日常路径，不暴露 Pi 的完整树管理界面。

### 暂不规划

当前不向用户展示上下文占用、压缩阈值和会话级 Token 或费用统计，也不提供手动压缩、自动压缩开关及重试开关。Pi 已自动处理压缩和重试，这些控制会把底层运行细节转移给用户，却不能改善日常对话体验。

图片输入等待统一附件能力；JSONL 或 HTML 导入导出、归档列表与恢复、分支摘要及节点标签也不在当前范围。只有出现明确的日常使用需求时，再重新评估这些能力。

### 后续版本

在具体产品需求明确后，再启用 Skills、Context Files、Prompt Templates、外部 Extensions、自定义工具和工具管理。内置 Extension 继续按已确认的产品能力逐项显式加载。
