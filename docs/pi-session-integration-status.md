# Pi SDK 会话能力对接现状

> 更新日期：2026-08-17  
> 对照版本：`@earendil-works/pi-coding-agent@0.84.1`

## 结论

当前已经完成 V0 所需的核心对话闭环：用户可以创建、恢复和切换持久会话，发送文本消息，查看流式回复、思考过程与工具运行，并控制会话模型、思考等级和 Agent 停止。

尚未对接的主要是 Pi 的高级会话能力，包括运行中追加消息、图片输入、手动上下文压缩、会话分支、导入导出及会话运行设置。Extensions、Skills 等资源能力则是当前阶段主动关闭，并非实现遗漏。

## 已对接能力

| 能力 | 当前实现 |
| --- | --- |
| 持久化会话 | 使用 Pi JSONL 会话文件保存，服务重启后仍可列出和继续 |
| 新建与切换会话 | 支持创建独立会话、按不透明 ID 打开已有会话 |
| 消息历史 | 从 Pi 当前分支投影完整结构化历史，保留压缩前消息和摘要 |
| 文本提示 | 支持纯文本 `prompt()`，通过前置校验后立即返回 |
| 流式事件 | 通过 SSE 转发 Pi JSON 事件 |
| 消息展示 | 支持文本、Markdown、思考、工具调用、工具结果和特殊消息 |
| Agent 生命周期 | 展示运行状态，并以 `agent_settled` 判断运行结束 |
| 工具运行 | 启用 Pi 默认的 `read`、`bash`、`edit`、`write` 工具 |
| 自动重试 | 展示模型调用和摘要生成的重试状态、次数与倒计时 |
| 自动上下文压缩 | 接收压缩事件，展示压缩状态和持久化摘要 |
| 停止 | 支持停止 Agent 运行或正在进行的上下文压缩 |
| 会话模型 | 支持按会话选择、持久化和恢复模型 |
| 思考等级 | 支持按当前模型能力选择、持久化和恢复思考等级 |
| 会话标题 | 读取并持久化 Pi `sessionName`，支持自动生成、手动重命名、当前会话 SSE 同步和多客户端列表轮询同步 |
| 生命周期管理 | 支持归档和永久删除会话 |
| 多客户端共享 | 多个客户端打开同一会话时共享 Runtime、消息和运行状态 |

## 尚未对接能力

### 1. 运行中追加消息

Pi 支持两种运行中消息：

- `steer`：当前助手轮次完成工具调用后，优先插入新指令。
- `followUp`：等待当前 Agent 运行自然结束后，再执行后续消息。

当前 Agent 运行时输入区被锁定，服务端也会返回忙碌错误。虽然 `queue_update` 事件已经随 Pi 事件流传输，但客户端没有消费其队列内容。

同时尚未对接：

- 查看待处理消息；
- 清空消息队列；
- 设置 `all` 或 `one-at-a-time` 投递模式；
- 停止运行后把未处理消息恢复到输入框。

### 2. 图片与多模态输入

Pi 的 `prompt()`、`steer()` 和 `followUp()` 均支持图片附件。客户端已经能够渲染历史消息中的图片，但发送接口当前只接受 `{ text }`。

尚未实现：

- 文件选择；
- 拖放或粘贴图片；
- 图片预览与移除；
- 图片编码、大小和 MIME 类型校验；
- HTTP 协议中的图片内容；
- 携带图片发送、steer 或 follow-up。

### 3. 手动上下文压缩

自动上下文压缩已经生效并可展示，但用户不能主动调用 Pi `compact()`。

尚未实现：

- 手动开始压缩；
- 提供自定义摘要指令；
- 开启或关闭自动压缩；
- 查看当前上下文占用和压缩阈值。

停止正在进行的压缩已经由通用停止操作覆盖。

### 4. 会话树、回退与分支

Pi 会话内部是由 `id` 和 `parentId` 组成的树，支持在同一文件内回退，也支持从历史节点创建新会话。

尚未对接：

- 获取和展示会话树；
- `navigateTree()` 回到历史节点；
- 对被放弃的分支生成摘要；
- 为节点或摘要设置标签；
- fork 新会话；
- clone 当前路径；
- 从指定用户消息重新开始。

当前“新建会话”和“切换会话”只覆盖独立会话文件的创建与打开，不等同于 Pi 的树形分支能力。

### 5. 导入与导出

尚未对接：

- 从 JSONL 文件导入 Pi 会话；
- 将当前分支导出为 JSONL；
- 将会话导出为 HTML；
- 从客户端选择导入来源或导出位置。

此外，驴打滚当前只支持归档，没有归档列表和恢复归档会话的入口。这属于产品会话生命周期缺口，不是 Pi `AgentSession` 的直接能力。

### 6. 会话统计与上下文状态

客户端目前能查看单条助手消息的模型、Token 和费用，但没有接入 Pi 的会话级统计。

尚未展示：

- 用户消息、助手消息、工具调用和工具结果数量；
- 会话累计输入、输出、缓存 Token；
- 会话累计费用；
- 当前上下文占用；
- 历次压缩前后的统计。

### 7. 会话运行设置

Pi 提供的以下设置尚未暴露：

- 自动重试开关；
- 自动上下文压缩开关；
- steering 和 follow-up 队列模式；
- 当前活跃工具列表；
- 动态启用或停用工具；
- Runtime 资源重新加载。

Pi 的模型循环和思考等级循环也未直接接入，但当前客户端已经提供模型选择器和思考等级滑块，因此没有必要重复实现循环操作。

### 8. 直接 Bash 与自定义消息

Agent 可以通过已启用的 `bash` 工具执行命令，但用户不能像 Pi 交互模式一样直接执行 Bash，也没有对接：

- `executeBash()` 直接命令；
- Bash 输出流和单独停止；
- 排除命令结果进入模型上下文；
- `sendCustomMessage()`；
- `sendUserMessage()` 的结构化内容入口。

这类能力不是 V0 对话闭环所必需。

## 当前主动关闭的 Pi 能力

创建 Pi 会话服务时，以下资源发现能力被显式关闭：

- Extensions；
- Skills；
- Prompt Templates 和斜杠命令；
- Context Files，包括自动发现 `AGENTS.md`；
- Themes。

系统提示词目前使用驴打滚内置的固定提示词，工具固定为 Pi 默认的四个工具。

这符合当前架构约束：Extension 只在出现已确认的具体功能需求时开发，当前阶段不预先搭建扩展基础设施。PRD 也将自定义工具和技能管理放在后续版本。

## 会话基础设施限制

### 全局单 Agent 运行

Pi 的不同 Runtime 可以分别运行，但驴打滚当前额外施加了全局单 Agent 约束：任意会话运行时，其他会话不能开始新的 Agent 运行。这是当前产品并行策略，不是 Pi SDK 的限制。

### SSE 断线恢复

当前 SSE 在建立订阅时会发送权威会话状态，也会缓存响应头就绪前产生的事件，但没有：

- 事件 ID；
- `Last-Event-ID` 恢复；
- 服务端事件缓冲和断线补发；
- 心跳；
- 重连后自动重新拉取消息历史。

因此浏览器断线期间的流式增量、工具进度和重试倒计时可能丢失。最终消息仍由 Pi 会话文件持久化，但客户端需要重新加载历史才能恢复。

## 文档与实现不一致

ADR-0006 记录“新会话使用 Pi `AgentSessionRuntime.newSession()`”。当前实现已经演进为：手动持久化 Pi 标准会话 header，然后使用 `SessionManager.open()` 为每个会话创建独立 Runtime。

当前产品行为符合 ADR-0008 的“每个已打开会话维护唯一 Runtime”，但 ADR-0006 的具体实现描述已经过时，应更新或由后续 ADR 覆盖。

## 建议优先级

### 第一批：补齐日常对话体验

1. 图片输入；
2. `steer` 和 `followUp`；
3. 队列状态展示与清空。

### 第二批：补齐上下文管理

1. 上下文占用展示；
2. 手动压缩；
3. 自动压缩与重试设置；
4. 会话级 Token 和费用统计。

### 第三批：补齐高级会话管理

1. 会话树浏览与回退；
2. fork、clone 和分支摘要；
3. JSONL 导入与导出；
4. HTML 导出；
5. 归档列表与恢复。

### 后续版本

在具体产品需求明确后，再启用 Skills、Context Files、Prompt Templates、Extensions、自定义工具和工具管理。
