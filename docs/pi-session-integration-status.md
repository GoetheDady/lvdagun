# Pi SDK 会话能力对接现状

> 更新日期：2026-08-18
>
> 对照版本：`@earendil-works/pi-coding-agent@0.84.1`

## 结论

当前已经完成 V0 所需的核心对话闭环：用户可以创建、恢复和切换持久会话，发送文本消息，在 Agent 运行期间继续排队或调整方向，查看流式回复、思考过程与工具运行，并控制会话模型、思考等级和 Agent 停止。

尚未对接的主要是 Pi 的高级会话能力，包括图片输入、手动上下文压缩、会话分支、导入导出及会话运行设置。外部 Extensions、Skills 等资源发现能力仍是当前阶段主动关闭，并非实现遗漏；待处理消息使用一个显式加载的驴打滚内置 Extension。

### 运行中消息与待处理消息

Pi 支持的两种运行中消息已经接入：

- `steer`：当前助手轮次完成工具调用后，优先插入新指令。
- `followUp`：等待当前 Agent 运行自然结束后，再执行后续消息。

用户在当前会话运行期间发送消息时，默认进入驴打滚的“待处理消息”区，而不是立即写入 Pi 队列。每条消息由当前 Runtime 分配稳定 ID，服务端通过 `pending_messages_changed` 广播完整权威快照，多个客户端据此展示相同的 FIFO 列表。

客户端没有直接把 Pi `queue_update` 事件投影成待处理消息列表。Pi 事件只提供 steering 和 follow-up 文本数组，没有可供逐条操作的稳定消息 ID；若以文本作为身份，重复文本、逐条删除和并发更新都会产生歧义。因此，待处理消息在移交前由驴打滚内置 Extension 管理，移交后才进入 Pi 原生队列：

- 默认排队：一次成功的 `agent_end` 只取 FIFO 首条，通过 `followUp()` 移交；最终失败时不移交，消息仍留在待处理区。
- 调整方向：用户点击指定消息的“调整方向”后，按稳定 ID 取出该条消息并通过 `steer()` 移交；Pi 拒绝时恢复到原位置。
- 逐条删除：只删除尚未移交的指定消息。
- 全部取回：从待处理区移除全部消息，并按原顺序放回当前客户端草稿。
- 清空：确认后丢弃全部尚未移交的消息，不影响已经进入 Pi 队列的消息。
- 停止：清空 Pi steering、follow-up 队列和驴打滚待处理区，中止当前运行，再把所有未处理文本按顺序恢复到发起停止操作的客户端草稿。

当前限制：

- 待处理消息跨服务重启持久化；
- 编辑或重新排序待处理消息；
- 设置 `all` 或 `one-at-a-time` 投递模式；
- 带图片的排队或调整方向消息。

## 尚未对接能力

### 1. 图片与多模态输入

Pi 的 `prompt()`、`steer()` 和 `followUp()` 均支持图片附件。客户端已经能够渲染历史消息中的图片，但发送接口当前只接受 `{ text }`。

尚未实现：

- 文件选择；
- 拖放或粘贴图片；
- 图片预览与移除；
- 图片编码、大小和 MIME 类型校验；
- HTTP 协议中的图片内容；
- 携带图片发送、steer 或 follow-up。

### 2. 手动上下文压缩

自动上下文压缩已经生效并可展示，但用户不能主动调用 Pi `compact()`。

尚未实现：

- 手动开始压缩；
- 提供自定义摘要指令；
- 开启或关闭自动压缩；
- 查看当前上下文占用和压缩阈值。

停止正在进行的压缩已经由通用停止操作覆盖。

### 3. 会话树、回退与分支

Pi 会话内部是由 `id` 和 `parentId` 组成的树，支持在同一文件内回退，也支持从历史节点创建新会话。

尚未对接：

- 获取和展示会话树；
- `navigateTree()` 回到历史节点；
- 对被放弃的分支生成摘要；
- 为节点或摘要设置标签；
- fork 新会话；
- clone 当前路径；
- 从指定用户消息重新开始。

当前“新建会话”和“切换会话”只覆盖独立会话文件的创建与打开，不等同于 Pi 的树形分支能力。

### 4. 导入与导出

尚未对接：

- 从 JSONL 文件导入 Pi 会话；
- 将当前分支导出为 JSONL；
- 将会话导出为 HTML；
- 从客户端选择导入来源或导出位置。

此外，驴打滚当前只支持归档，没有归档列表和恢复归档会话的入口。这属于产品会话生命周期缺口，不是 Pi `AgentSession` 的直接能力。

### 5. 会话统计与上下文状态

客户端目前能查看单条助手消息的模型、Token 和费用，但没有接入 Pi 的会话级统计。

尚未展示：

- 用户消息、助手消息、工具调用和工具结果数量；
- 会话累计输入、输出、缓存 Token；
- 会话累计费用；
- 当前上下文占用；
- 历次压缩前后的统计。

### 6. 会话运行设置

Pi 提供的以下设置尚未暴露：

- 自动重试开关；
- 自动上下文压缩开关；
- steering 和 follow-up 队列模式；
- 当前活跃工具列表；
- 动态启用或停用工具；
- Runtime 资源重新加载。

Pi 的模型循环和思考等级循环也未直接接入，但当前客户端已经提供模型选择器和思考等级滑块，因此没有必要重复实现循环操作。

### 7. 直接 Bash 与自定义消息

Agent 可以通过已启用的 `bash` 工具执行命令，但用户不能像 Pi 交互模式一样直接执行 Bash，也没有对接：

- `executeBash()` 直接命令；
- Bash 输出流和单独停止；
- 排除命令结果进入模型上下文；
- `sendCustomMessage()`；
- `sendUserMessage()` 的结构化内容入口。

这类能力不是 V0 对话闭环所必需。

## 当前主动关闭的 Pi 能力

创建 Pi 会话服务时，以下外部资源发现能力被显式关闭：

- 外部 Extensions；
- Skills；
- Prompt Templates 和斜杠命令；
- Context Files，包括自动发现 `AGENTS.md`；
- Themes。

系统提示词目前使用驴打滚内置的固定提示词，工具固定为 Pi 默认的四个工具。待处理消息使用 `resourceLoaderOptions.extensionFactories` 显式加载一个命名内联 Extension；`noExtensions: true` 继续阻止磁盘目录发现外部 Extension。

这符合当前架构约束：Extension 只在出现已确认的具体功能需求时开发，当前阶段不预先搭建扩展基础设施。PRD 也将自定义工具和技能管理放在后续版本。

## 会话基础设施限制

### 全局单 Agent 运行

Pi 的不同 Runtime 可以分别运行，但驴打滚当前额外施加了全局单 Agent 约束：任意会话运行时，其他会话不能开始新的 Agent 运行。这是当前产品并行策略，不是 Pi SDK 的限制。

### SSE 断线恢复

当前 SSE 在建立订阅时会发送权威会话状态，也会缓存响应头就绪前产生的事件，但没有：

- 事件 ID；
- `Last-Event-ID` 恢复；
- 服务端事件缓冲和断线补发；
- 心跳；
- 重连后自动重新拉取消息历史。

因此浏览器断线期间的流式增量、工具进度和重试倒计时可能丢失。最终消息仍由 Pi 会话文件持久化，但客户端需要重新加载历史才能恢复。

## 建议优先级

### 第一批：继续补齐日常对话体验

1. 图片输入；

### 第二批：补齐上下文管理

1. 上下文占用展示；
2. 手动压缩；
3. 自动压缩与重试设置；
4. 会话级 Token 和费用统计。

### 第三批：补齐高级会话管理

1. 会话树浏览与回退；
2. fork、clone 和分支摘要；
3. JSONL 导入与导出；
4. HTML 导出；
5. 归档列表与恢复。

### 后续版本

在具体产品需求明确后，再启用 Skills、Context Files、Prompt Templates、外部 Extensions、自定义工具和工具管理。内置 Extension 继续按已确认的产品能力逐项显式加载。
