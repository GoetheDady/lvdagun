## 1. 产品概述

一句话：**一个部署在自己电脑上的个人 AI 管家，V0 阶段只做一件事——能对话。**

长期愿景（不在 V0 范围内）：多设备访问（手机）、设备感知、控制本机与多台终端、长期记忆、语音交互。

## 2. 背景与定位

- **市场背景**：通用 Agent Harness（Claude Code / Codex / Hermes / 微软 Agent Framework 等）已成红海并被巨头与开源商品化；个人 agent 的差异化在于**记忆与个性化**——只服务一个人，知道用户的偏好与习惯。
- **产品定位**：个人专属 AI 管家。单用户、本地优先、数据不出本机。
- **技术底座**：Pi Agent SDK（@earendil-works/pi-coding-agent，OpenClaw 底层引擎）提供 Agent 运行时；本机 Web 服务 + 浏览器提供交付形态，Electron 壳后置。

## 3. 产品架构

中心辐射式：**Agent Hub（本地常驻内核）** + **多端客户端**。

- **Agent Hub**：常驻本地进程，负责 Agent 运行时（模型对话、工具执行、上下文管理）。V0 承载于本机 Web 服务进程（CLI 启动）；V2 起开放局域网/公网端口。
- **客户端**：V0 为浏览器页面（无状态接入端）；V1 增加 Electron 壳（窗口 + 托盘 + 加载本地页面）。
- **形态**：`lvdagun serve` 启动本地服务并打开浏览器。关标签页 ≠ 退出——服务常驻，`lvdagun stop` 才结束进程。
- **设备感知**（V1+）：客户端上报 deviceId/deviceType，Hub 在对话上下文中感知当前设备。

## 4. 用户与核心场景

- **用户**：开发者本人（单用户、单机）
- **核心场景**：启动服务 → 浏览器自动打开 →（首次）配置模型 → 跟 AI 对话 → 关标签（不停止服务）→ 回来接着聊，上下文还在

## 5. V0 功能范围

### 5.1 功能需求

| 编号 | 功能         | 描述                                                              | 优先级 |
| ---- | ------------ | ----------------------------------------------------------------- | ------ |
| F1   | 对话         | 发送消息，AI 流式回复（打字机效果）                               | P0     |
| F2   | 服务常驻     | 关闭浏览器标签页后服务继续运行，重新访问即恢复对话                | P0     |
| F3   | 会话保持     | 关标签期间对话上下文保留（进程内存），恢复访问后能继续聊          | P0     |
| F4   | 模型接入     | 可配置一个 LLM（API Key），V0 支持任一主流模型                    | P0     |
| F5   | 退出机制     | 只有 `lvdagun stop` 才真正结束服务进程                            | P0     |
| F6   | 首次配置向导 | 首次访问引导选择 provider、填写 API Key、选择 model，完成后进入对话页 | P0 |

### 5.2 向导细节（F6）

三步结构：① 选择 Provider（Anthropic / OpenAI / DeepSeek / MiniMax / Ollama 本地等）→ ② 填写 API Key（含"测试连接"，Ollama 本地跳过此步）→ ③ 选择 Model → 完成进入对话页。配置完成后再次访问不再出现；设置页可随时修改，与向导共享同一套配置。

### 5.3 V0 明确不做

设备感知、手机端、长期记忆持久化、自定义工具、语音、多机控制、多用户。

## 6. 页面划分

### 6.1 V0 页面清单

| 页面       | 类型                     | 主要内容                                                     |
| ---------- | ------------------------ | ------------------------------------------------------------ |
| 配置向导页 | 引导页（仅首次访问出现） | Step1 选 provider → Step2 填 Key（测试连接）→ Step3 选 model |
| 对话页     | 主页面                   | 消息流、输入框、发送按钮、流式渲染、清空会话（带确认）       |
| 设置页     | 次页面                   | 模型选择、API Key 状态（掩码显示）、关于；与向导共享配置     |
| 服务命令   | 系统组件（CLI）          | `lvdagun serve` 启动并打开浏览器、`lvdagun stop` 停止服务    |

### 6.2 页面流程

```
启动服务 ──(首次访问)──> 配置向导页 ──(完成)──> 对话页
启动服务 ──(已配置)──> 对话页
对话页 ──(关标签)──> 服务常驻（会话上下文保留）
重新访问 ──> 对话页（上下文保留）
`lvdagun stop` ──> 服务进程结束
```

## 7. 界面设计要点（摘要，详见设计规格）

- **页面**：浅色主题，品牌主色 #0F6E56。
- **对话页**：用户消息右对齐主色气泡、AI 消息左对齐浅色气泡；流式输出带闪烁光标；空状态显示欢迎语与示例建议；代码块深色底等宽字体。
- **错误态**：AI 气泡内红色提示 + 重试按钮。
- **输入区**：多行输入框，Enter 发送、Shift+Enter 换行；发送中按钮转圈。

## 8. 非功能需求

- 本地运行，对话数据不出本机
- 启动到可对话 < 3 秒
- 常驻内存 < 300MB
- 本机安全：本地服务监听 localhost，API 需 token 校验，防 CSRF
- 界面语言：中文；视觉：浅色简洁

## 9. 验收标准（V0 完成定义）

1. `lvdagun serve` 启动本地服务并自动打开浏览器
2. 首次访问出现配置向导，完成 provider + API Key + model 配置后进入对话页
3. 再次访问不再出现向导，直接进入对话页
4. 输入"你好"，AI 以流式方式完整回复
5. 关闭标签页 → 服务仍在运行，进程未退出
6. 重新访问 → 对话记录仍在，能继续聊
7. `lvdagun stop` → 服务进程完全结束
8. 停止后重新 `lvdagun serve`，能正常再次对话（V0 不要求记忆恢复，只要求不报错）
9. 无 token 的 API 请求被拒绝，带 token 的请求正常

## 11. 附录：技术方案概要（V0）

- **技术栈**：Express + React + Pi Agent SDK + TypeScript，均使用最新版本；包管理用 bun
- **进程模型**：常驻 Node 服务进程承载 Agent Session，浏览器为客户端；服务由 CLI 启动/停止
- **模型**：经 Pi 统一模型层接入，支持多 provider；本地可用 Ollama
- **配置存储**：本机文件（`~/.lvdagun/`），Key 仅存本机
